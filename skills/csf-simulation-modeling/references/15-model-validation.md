# 模型构建与验证契约

用于读题、形式化、写仿真和选择算法。模型未验证时，先形成可以执行的最小实验，不以论文篇幅替代验证。

## 建模产物

在项目 `model-spec.md` 记录：

| 项目 | 必须明确的内容 |
|---|---|
| 任务边界 | 决策对象、时间/空间范围、给定条件、交付物、平台与计算预算 |
| 主体 | 类型、数量、异质性、生命周期、行为规则；区分仿真主体与 LLM 协作代理 |
| 状态与信息 | 全局状态、各主体局部观测、通信拓扑/延迟；哪些信息只在训练时可见 |
| 动作与约束 | 动作空间、合法动作、容量/资源/安全约束、冲突解决与决策频率 |
| 时间语义 | DES/固定步长/连续时间选择理由；同一时刻事件顺序；终止与预算截断 |
| 参数 | 符号、单位、取值/范围、来源；实测、文献和假设分开标记 |
| 输出 | KPI 公式/单位/优化方向、失败定义、可观察轨迹；奖励与 KPI 分开 |
| 随机性 | 外生到达/需求/运动/策略分别建随机数流；保存种子与环境版本 |

ABM、DES 和 MARL 是不同层次：ABM/DES 描述环境演化，优化/RL 描述决策策略。多主体存在不意味着必须使用 MARL；Gym 单环境 PPO 也不自动成为 IPPO。

## 方法选择

先运行机理卡/方法库获取候选，再检查候选的前提，不把关键词分数当适用性证明：

执行方式见 [17-context-selection.md](17-context-selection.md)：用 `method-context.json` 保留未知/肯定/否定与依据，`csf_select.py --context` 输出可追溯前提审查。内部验证的最小示例见 [validated-dispatch](../../../examples/validated-dispatch/README.md)。

1. 规则基线：在相同约束、信息与决策频率下能否完成任务？
2. 解析参照/小规模精确解：是否可计算容量界、守恒式或最优解用于校验？注明界的方向与成立条件。
3. 主方法：哪些基线失效由目标机制解释？复杂方法是否需要不存在的数据或平台依赖？
4. MARL：确定同质/异质、合作/竞争、离散/连续动作及部分可观测性，再选 IPPO/MAPPO/VDN/QMIX。共享参数需要主体标识或足够区分的观测；分散执行不得读取特权全局状态。
5. 消融：保持预算、输入场景和评估流一致，一次移除目标机制；信息更多的 oracle 单独列为参照。

不固定必须凑足多少类算法；覆盖能够回答题目与研究假设的必要对照即可。

## 验证顺序与验收证据

- **代码验证 verification**：守恒、非负队列、容量不超限、动作合法性、终止条件。测试空系统/单主体/零容量/无限容量等适用极端情形；可用解析解或手算小实例对拍。
- **数值验证**：时间步减半是否改变结论？同一输入与种子是否可复现？跨 Python/Julia 对拍使用同一外生事件表，而非假设相同整数 seed 会产生相同随机序列。
- **模型有效性 validation**：用未参与校准的观测或公开基准比较分布与动态，而不仅看均值。没有外部数据时明确“机制验证/内部一致性”，不能声称已验证现实准确性。
- **参数校准**：报告目标、参数范围、可辨识性与留出数据。优化器收敛不代表参数唯一可识别。
- **实验设计**：终止型仿真与稳态仿真分开；稳态解释预热期、运行长度及自相关。主体/时间步/同一训练模型下多个 episode 不能直接当独立训练重复。

把每项适用检查的命令、输入、容差依据、结果和产物路径记录在 `verification.md`。无效模型先修正，再产生正式实验数值；不适用项写原因。

## 原始结果与停止条件

先保存逐运行指标和失败状态，再汇总；协议见 [16-evidence-statistics.md](16-evidence-statistics.md)。校准、调参、验证和最终测试分开，测试集不用于选最优参数。公共随机数 CRN 的配对必须共享外生场景/事件，而不是只复用 seed 标签。

只有模型契约、适用验证、规则基线与原始结果均完成，才进入主方法大规模实验。训练到预算仍未收敛可以报告失败/预算结果，不能补造 KPI。
