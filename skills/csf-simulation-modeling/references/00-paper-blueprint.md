# 论文蓝图（先于一切建模）

初稿阶段的核心不是一次做完，而是**先定宏观模型与图表分布、理清叙事框架、控制内容量**。拿到赛题后，第一件事是产出“论文蓝图”，再进入细致建模。本文件是 `csf-simulation-modeling` 的**第一步**，任何时候都先读它。

## 一、蓝图四要素

1. **宏观模型**：问题形式化（决策变量 / 目标 / 约束）+ 子模型划分 + 方法族选型（含前沿候选与选择理由）。
2. **章节蓝图**：章节数量、每章解决什么难题、预计页数与内容量、与赛题各问的对应关系。
3. **图表蓝图**：每张图/表的类型、叙事作用、与正文哪段结论关联。
4. **内容量把控**：在哪里展开推导、在哪里放算例、在哪里做敏感性、参考文献数量目标。

## 二、建模三问（避免“套用方法”）

先自己给问题建数学形式，再选方法；顺序不能反。

1. **问题本质是什么？** 组合优化 / 随机过程与排队 / 多主体博弈 / 控制与决策 / 统计推断？
2. **决策变量、目标函数、约束分别是什么？** 用符号写出来（哪怕粗糙），明确“要决定什么、优化什么、受什么限制”。
3. **前沿方法族里哪一类与这个形式最匹配？** 给出首选与备选，并写一句“为什么”：图结构状态→GNN+RL；序列生成→PtrNet/Attention Model；随机到达→DES+OvS；多目标→NSGA-II/III；多主体→MARL。出处查 `07-methods-library.md`。

## 三、章节蓝图模板（章节 → 解决什么 → 内容量）

| 章节 | 解决什么难题 | 大致内容量 |
|---|---|---|
| 1 问题重述 | 把赛题翻译成 3–6 项可求解任务 | 0.5–1 页 |
| 2 问题分析 | 每个问题的技术路线与相互依赖 | 1–1.5 页 |
| 3 基本假设 | 适用范围 + 被放宽后的影响 | 0.5–1 页 |
| 4 符号说明 | 符号/含义/单位/来源四列表 | 0.5–1 页 |
| 5 模型建立与求解 | 每个子问题一节：机理→定义→推导→求解→算例→检验→小结 | 占总页 60%+ |
| 6 模型评价与推广 | 优点/局限/推广 | 0.5–1 页 |
| 参考文献 | 竞赛 10–15 篇；投稿 30–60 篇 | 1–2 页 |
| 附录 | 可复现代码 1–2 页 | 1–2 页 |

**铁律**：每个子问题都走“模型建立→求解→问题结论→检验分析→小结”五段，缺一段就说明内容量不够或模型没讲清。

## 四、图表蓝图模板（类型 → 叙事作用 → 关联正文）

| 图/表 | 类型 | 叙事作用 | 关联正文 |
|---|---|---|---|
| 图 1 | 系统/机制架构图 | 讲清系统如何运作、资源如何耦合 | 模型建立开头，“如图 1 所示” |
| 图 2 | 主结果图（过程曲线/收敛） | 直接支撑 KPI 结论 | 结果章，“由图 2 可见” |
| 图 3 | 策略/方法对比图 | 基线 vs 本文，证明改进 | 对比段，“图 3 表明” |
| 图 4 | 瓶颈/敏感性/稳健性图 | 支撑检验与调参 | 检验段 |
| 表 1 | 符号表 | 术语统一 | 符号说明 |
| 表 2 | 参数/数据表 | 数据来源与取值 | 模型建立 |
| 表 3 | 指标对比表 | 数值结论一表看清 | 结果章 |

**关联铁律**：每张图/表在正文必须有一句明确引用并说明“读者应读出什么结论”，不能只宣布“见图 X”。

## 五、内容量把控清单

- [ ] 模型章占比 ≥60%，摘要与结论一页内
- [ ] 每个子问题有 5 段完整结构
- [ ] 至少 1 条命题/性质给出证明或算例
- [ ] 推导逐步写、每步标依据，不跳步
- [ ] 数值带均值±标准差与重复次数
- [ ] 参考文献 10–15 篇（方法出处 + 场景代表作 + 前沿综述，三类都要有）

## 六、排版铁律（防粘连）

- 图注与图像分离：图注在图下方居中、单独成行，不与图内文字重叠；LaTeX 用 `\caption{}`，不用图内嵌标题。
- 图内文字不叠数据：柱顶标注放在误差棒之上并留 3–5pt 间距；曲线标注避开峰值；图例放数据最稀处。
- 图内字号 ≤ 正文；中文标签短、保留英文符号缩写。
- 生成图后逐图放大检查“粘连、越界、字号不一致”。
